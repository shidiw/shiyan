 一、最核心的一条线

我们之前 Struct3D 真正要解决的问题，其实可以压缩成：


点 / 几何
    ↓
局部几何结构
    ↓
Unit
    ↓
Unit 之间的关系
    ↓
Assembly
    ↓
Emergent Object
    ↓
Object 之间的关系
    ↓
Instance
    ↓
World


所以：


Unit
不是 primitive 的同义词

Object
不是人为给点云贴的类别

Instance
不是简单的 instance ID

World
也不是一个普通 point cloud tensor


它们都是结构层级中的不同数学对象。

---

 v0.0：Geometry → Energy

最初的问题不是：


“怎么设计一个神经网络？”


而是：


一个三维几何对象，
为什么可以被划分成若干稳定的结构单元？


因此第一步必须从几何本身开始。


E ⊂ ℝ³


把三维物体看成几何集合，而不是直接看成：


X ∈ ℝ^(N×3)


然后引入 Energy：


F(E)


Energy 的作用不是为了“训练神经网络”，而是描述：


一个区域作为一个整体，
在几何上是否稳定。


所以最初的逻辑是：


Geometry
    │
    ▼
Measure
    │
    ▼
Energy
    │
    ▼
Stability


即：


几何结构
   ↓
几何代价
   ↓
稳定区域


这是后面 Unit Emergence 的基础。

---

 v1.x：Energy → Unit

有了 Energy 后，才出现真正关键的问题：


什么叫 Unit？


不是：


Unit = 一个人工定义的 primitive


而是：


Unit = 从几何 Energy 中稳定出现的局部结构


所以：


Geometry
    ↓
Energy
    ↓
Energy-minimizing / stable region
    ↓
Unit


这就是我们一直强调的：


Unit Emergence


也就是说，Unit 是 emergent structure。

直观地看：


        Geometry
            │
     ┌──────┼──────┐
     ▼      ▼      ▼
   region  region  region
     │      │      │
     ▼      ▼      ▼
    E₁     E₂     E₃
     │      │      │
     └──────┼──────┘
            ▼
        stable units
            │
       ┌────┼────┐
       ▼    ▼    ▼
      U₀   U₁   U₂


因此我们后面的 Struct3D 不应该反过来：


先规定：
plane
sphere
cylinder
...


然后强迫世界去适应这些 primitive。

原来的理论方向是：


World
  ↓
Geometry
  ↓
Energy
  ↓
Stable structure
  ↓
Unit


---

 v2.x：Unit → Relation → Assembly

当 Unit 出现之后，一个 Unit 仍然不能解释完整物体。

例如：


U₀ = plane-like unit
U₁ = sphere-like unit


真正重要的问题变成：


U₀ 和 U₁ 为什么属于同一个结构？


于是出现：


Unit Relations


即：


U₀ ───── R₀ ───── U₁


因此：


Units
  │
  ▼
Relation Graph
  │
  ▼
Unit Relations
  │
  ▼
Assembly


这一步非常重要，因为：


Unit ≠ Object


Object 是由：


Units + Relations


共同产生的。

所以：


Assembly = {Units, Relations}


然后进一步产生：


Emergent Object


---

 Emergence：Unit → Assembly → Object

因此我们之前的 Emergence 思想可以用这条链表示：


local geometry
      ↓
     Unit
      ↓
 Unit relations
      ↓
   Assembly
      ↓
 emergent object


也就是说：


Object 不是 primitive 的简单集合


而是：


Object = relational assembly of Units


这也是为什么后来我们必须把：


Object Composition


作为 Structural Distance 和 Structural Matching 的测试对象。

因为如果：


U₀ + U₁


换成：


U₀ + U₁ + U₂


那么结构本身已经发生改变。

---

 v2.x / v3.x：Hierarchy

当 Assembly 和 Object 出现之后，就自然出现层级。

我们之前的结构可以整理成：


Unit
  │
  ▼
Assembly
  │
  ▼
Object
  │
  ▼
Instance


但它不是简单的树标签，而是一个结构层级系统。

更直观：


World
 │
 ├── Instance I₀
 │      │
 │      └── Object O₀
 │              │
 │              ├── Unit U₀
 │              └── Unit U₁
 │
 └── Instance I₁
        │
        └── Object O₁
                │
                ├── Unit U₂
                └── Unit U₃


因此：


Unit
 ↓
Object
 ↓
Instance


描述的是不同尺度上的结构。

---

 v3.x：World

当：


Units
Objects
Instances
Relations


全部出现以后，就不能再只研究一个 Object。

于是定义：


W = Structural World


可以直观理解成：


                  WORLD
                    │
       ┌────────────┼────────────┐
       │            │            │
       ▼            ▼            ▼
     Units        Objects     Instances
       │            │            │
       └────────────┼────────────┘
                    │
                    ▼
                 Relations


所以 World 是前面所有结构的统一载体。

也就是说：


Unit
  ↓
Object
  ↓
Instance
  ↓
World


不是四个独立概念。

---

 v3.8：World → Structural Distance

到了 World，才有必要问：


两个结构世界到底有多不同？


于是：


D(W₁,W₂)


成为 Structural Distance。

它不是普通：


Euclidean distance


也不是简单：


point-wise L2


而是比较：


World₁
   ↕
World₂


之间的结构差异。

因此 v3.8 验证的那些性质就非常自然：


D(W,W) = 0


以及：


D(W₁,W₂) = D(W₂,W₁)


还有：


D(W₁,W₃)
≤
D(W₁,W₂) + D(W₂,W₃)


同时：


Unit relabeling
Object relabeling
Instance relabeling
Relation relabeling
Rigid transform


不应该改变结构。

所以：


same structure
    ↓
D = 0


而：


primitive mutation
object mutation
instance mutation
relation mutation
    ↓
D > 0


这正是你刚刚 v3.8 最终跑出来的 23/23 PASS 所验证的东西。

---

 v3.9：Structural Distance → Structural Matching

但是 Distance 只告诉我们：


“两个 World 差多少？”


它没有告诉神经网络：


“哪个 Unit 对应哪个 Unit？”


所以自然需要下一步：


Structural Matching


即：


W₁                         W₂

U₀ ─────────────────────── U₀'
U₁ ─────────────────────── U₁'
U₂ ─────────────────────── U₂'
U₃ ─────────────────────── U₃'

O₀ ─────────────────────── O₀'
O₁ ─────────────────────── O₁'

I₀ ─────────────────────── I₀'
I₁ ─────────────────────── I₁'

R₀ ─────────────────────── R₀'
R₁ ─────────────────────── R₁'


因此：


Structural Distance
       ↓
知道“差多少”
       ↓
Structural Matching
       ↓
知道“谁对应谁”


这就是 v3.9 的理论位置。

而 v3.9 最终已经验证：


Matching
    ↓
Unit correspondence
Object correspondence
Instance correspondence
Relation correspondence
    ↓
Neural supervision target


所以它第一次真正把 Struct3D 的数学结构和神经网络接口接起来。

 v4.0：Matching → Representation

然后出现最后一个问题：


神经网络最终需要什么？


如果每次都直接操作：


World
Graph
Correspondence
Distance


神经网络很难直接使用。

所以需要：


Structural Representation


即：


World
  ↓
Canonical Structural Form
  ↓
Invariant Structural Form
  ↓
Structural Representation
  ↓
Vector


你刚刚跑出的 v4.0 就是在验证这一层。

最终：


W
 ↓
Canonical Form
 ↓
Invariant Form
 ↓
23-dimensional Representation


因此 v4.0 的位置不是重新定义 World，而是：
把已经建立起来的 Structural World
转换成可计算、可比较、可供神经网络使用的结构表示。

============================================================
二、v0.0：问题起点——Geometry 不是 Structure
==================================

最初的问题并不是：

“怎样训练一个更好的点云网络？”

而是：

给定一个三维几何对象，怎样从原始几何中得到一个比点本身更高层的结构？

原始输入可以抽象为点集：

P = {x_i}_{i=1}^N,
x_i ∈ R^3

但单纯的点集没有回答：

1. 哪些点属于同一个局部结构？
2. 什么是一个最小结构单元？
3. 哪些结构单元组合成 Part？
4. 哪些 Part 组成 Object？
5. Object 之间是什么关系？
6. 为什么这些结构会“自然出现”？

因此最初提出的核心方向是：

Geometry → Structure

============================================================
三、v0.1：从点到 Geometry
===================

随后 Geometry 不再只表示 xyz，而开始引入局部几何量。

核心几何信息包括：

位置：
x_i ∈ R^3

法向：
n_i ∈ S^2

曲率：
κ_i

以及局部邻域关系。

因此一个点的局部几何状态可以理解成：

g_i = (x_i, n_i, κ_i, ...)

这一阶段的重要思想是：

Structure 不能直接从 point identity 定义，

而应该从 geometry 的局部关系产生。

因此开始形成：

P
→ Local Geometry
→ Geometric Field

============================================================
四、v0.2：Geometry Field
=====================

这一阶段开始把整个点云看成一个几何场，而不是孤立点集合。

可以写成：

G(P) = {g_i}_{i=1}^N

并进一步构造点之间的结构关系。

两个点之间的局部几何差异至少包括：

位置差异
D_x(i,j)

法向差异
D_n(i,j)

曲率差异
D_κ(i,j)

因此开始出现结构兼容性思想：

# C(i,j)

w_d D(i,j)
+
w_n N(i,j)
+
w_k K(i,j)
+
w_b B(i,j)

这里的含义已经明确：

两个局部区域越几何兼容，
越可能属于同一个结构。

============================================================
五、v0.3：Structural Graph
=======================

Geometry Field 进一步转化为图。

定义：

G_s = (V,E)

其中：

V = local geometric elements

E = structural compatibility relations

边权反映两个局部元素之间的几何兼容程度。

因此：

Geometry
↓
Geometry Field
↓
Structural Graph

这一阶段非常关键，因为之后的 Unit、Object、Relation 都不再只是人为标签，而开始可以建立在图结构上。

============================================================

表示边界代价。

因此 Energy 不只是“训练 loss”。

它的理论角色是：

用一个统一泛函判断：

============================================================
八、Emergence：为什么 Unit 可以“出现”
===========================

当时讨论 Emergence 时，核心问题是：

如果 Unit 是人为定义的，那么 Struct3D 就只是换了一套名字。

所以必须解释：

Unit 为什么从 Geometry 中出现？

主逻辑是：

对于候选区域 E，

计算其结构能量：

F(E)

如果一个区域内部具有较高的几何一致性，同时分裂会增加总体结构代价，那么该区域就具有成为一个稳定结构单元的倾向。

因此：

Geometry
↓
Energy landscape
↓
Stable region
↓
Unit

这里的 Emergence 不是“神经网络自己学出来”这么简单。

它指：

结构实体可以作为能量优化后的稳定状态出现。

三十七、最简理论闭环
==========

最后可以把整个 Struct3D 理论压缩成一句非常重要的话：

Geometry determines Energy.

Energy determines stable Partition.

Partition determines Units.

Units determine Composition.

Composition determines Objects.

Objects instantiate into Instances.

Instances interact through Relations.

Relations organize Hierarchy.

Hierarchy forms a World.

Worlds are compared modulo structural equivalence.

Equivalence induces Quotient.

Quotient admits Canonical Form.

Canonical Form induces Invariant.

Invariant supports Structural Distance.

Distance supports Structural Matching.

Matching and Invariant Structure produce Structural Representation.

Structural Representation becomes the input / supervision basis of Neural Struct3D.

这就是目前我们已经走到的：

**v0.0 → v4.0 → Neural Struct3D**

而不是：

**v0.0 → v4.0 → v4.1 → v4.2 → v4.3 → Neural Struct3D**。

另外，必须特别保留一个你前面一直强调的审计结论：**v0.x 到 v2.x 的 Energy → Partition → Unit → Emergence → Hierarchy 这一段，在现有历史记录中还没有完整保存当时的逐字原始数学推导；不能拿 v3/v4 的结果倒推去“补齐”它。**当前能确认的早期核心式就是当时已经明确过的 `E = E_fit + λ_c C + λ_b B` 以及兼容性能量 `C(i,j)=w_dD+w_nN+w_kK+w_bB`。因此上面的时间线保留了原主链，但没有伪造缺失的原始公式。
